

HoneLENS is the research side panel of the HoneNurse family. It is built on the HoneNurse brand identity v1.0, which wins every conflict. Concise, calm, exact: hierarchy and spacing do the work before decoration. If an element tells the student nothing, delete it.

HoneLENS uses no AI. Never draw sparkles, chat bubbles, wands, glows or anything that suggests "magic". Every result comes from rules, math, public metadata lookups or the student's own input, and the interface should look like it.

Content

  • Reader. A stressed US nursing student with an assignment due. Direct, encouraging, never alarmist. A doesn't-match result is direction, not a verdict.
  • Sentence case everywhere. No all-caps labels, kickers or buttons. Product names keep their own spelling: HoneNurse, HoneLENS.
  • Plain language. Spell out every acronym at first use ("NNT (number needed to treat)"). Explain each technical term once in a PlainTerms box.
  • Say what was checked, never more. Write "No matching update record found in Crossref on Oct 4, 2026", never "not retracted". Write "nearest fit; check your course's table", never "Level II". Never write "verified peer-reviewed", "safe dose", "AI-proof", "approved".
  • Buttons are verbs. "Check this page", "Add criteria", "Copy citation", "See Pro plans".
  • Upgrade copy is one calm sentence that names the feature: "Word export is part of HoneLENS Pro." No pop-ups, timers, countdowns or discounts.
  • US English and US spelling (judgment, color).
  • No emoji, no exclamation marks, no confetti or streak fireworks.

Color

Near-monochrome. hn-navy leads, hn-teal is the one accent, the page stays hn-paper. Every color has one job:

MeaningInkFillUse for
Explains, matches, selected, primaryhn-tealhn-teal-tintMatches chip, "In plain terms", primary button, kicker, selected segment
Needs your actionhn-amberhn-amber-tintDoesn't match, student-confirm needed, wrong answer, lookup error, "In your assignment", retracted
Unknown, metadatahn-slatehn-panelUnknown chip, offline, hints, timestamps
Patient danger onlyhn-redhn-red-tintDo Not Use abbreviations. Nothing else
  • Set body text in hn-navy on hn-paper; raised surfaces (cards, inputs, tables) are hn-white.
  • Teal is noticed, never flooded: one primary button per screen, no teal backgrounds larger than a chip or callout.
  • Red never marks an error, a wrong answer or a retracted paper. A wrong dosage answer is amber.
  • Retracted sources are amber with the ban icon, the word "Retracted", a 6 px bar and the notice link.
  • Color never works alone. Every state carries an icon and a word, so it reads in grayscale and for color-blind students.
  • hn-teal-light sits on a navy fill in the light theme only. In dark, hn-navy is light, so use hn-teal.
  • hn-hair is for dividers only; any control boundary uses hn-field (≥ 3.5:1).
  • Dark theme: same roles, softer values from the brand doc. Text pairs stay ≥ 4.8:1 (most ≥ 7:1). Table headers stay a dark band via hl-table-head.

Type

One family, three voices. The typeface tells the student what kind of attention the text needs.

  • IBM Plex Sans, semibold only: act, navigate, scan. Buttons, labels, tabs, chips, headings. Styles section, title, display, label, kicker, nav.
  • IBM Plex Serif: read, understand, reason. Explanations, worked steps, notes, input values. Style body (17/1.6); body-compact (16/1.5) in tables and dense rows. Never below 16 px; small (14 px, hn-slate) for metadata only.
  • IBM Plex Mono: measure, calculate, verify. Doses, units, ratios, CIs, PMIDs, DOIs, timers. Styles value, value-strong, timer. Tabular figures.
  • Side panel screen title = section (22 px). Full-tab page title = title (28 px). display (40 px) only on full-tab heroes (pricing).
  • Bundle the font files with the extension. No remote fonts. Stack falls back to Segoe UI / Georgia / Consolas.

Space and layout

  • 4 px grid: hn-s1 4 · hn-s2 8 · hn-s3 12 · hn-s4 16 · hn-s5 24 · hn-s6 32 · hn-s7 48 · hn-s8 64.
  • Side panel: design at hl-panel-min (360 px), stay fluid to hl-panel-max (480 px), 16 px gutters (hn-s4).
  • One idea per screen: kicker, one-sentence title, one focal element, then nothing. A mostly empty lower half means the screen is done.
  • Anything wider than the panel (evidence matrix, audit report, EBP workspace) opens a full-tab page at hl-tab-width (1280 px).
  • Reading lines stay under hl-measure (68ch).

Shape, borders, elevation

  • Corners: hn-radius (4 px) on controls, hn-radius-lg (8 px) on cards and panels. hl-radius-pill on the toggle only. No heavy rounding.
  • corner-shape: squircle is applied where supported, with the radius scaled 1.5× so the corner reads the same size; everywhere else it is a plain border-radius.
  • Structure comes from 1 px hairlines. Cards, tables, callouts and forms have no shadow.
  • One float shadow, hl-shadow-float, for things that float: toast, menus, sticky header once content scrolls under it. One inset, hl-shadow-pressed, for pressed controls.
  • Callouts use a 4 px left bar (hn-callout-bar); danger and retracted use 6 px (hl-callout-bar-danger). This is the brand's own callout form.

Glass

Only two surfaces: the sticky panel header (PanelHeader) and the Pro upgrade card (UpgradeCard). hl-glass tint, backdrop-filter: blur(hl-glass-blur) (max 12 px), 1 px inner hl-glass-edge. Solid fallback (hn-paper / hn-white) when backdrop-filter is unsupported, under prefers-reduced-transparency, or when <html data-transparency="reduced"> is set from Settings. Never on tables, forms, rows or assignment content.

Motion and attention

  • Transition only background-color, border-color, box-shadow, transform; 120–180 ms (hl-dur-fast, hl-dur-base, hl-dur-slow) on hl-ease. Never animate width, height, top or left.
  • Hover: a 5–6 % tonal shift (hl-surface-hover, hl-teal-hover) plus at most 1 px lift on buttons.
  • Pressed: scale(.98) + hl-shadow-pressed.
  • Focus-visible: 2 px hn-focus ring, 2 px offset (hl-focus-width, hl-focus-offset); ≥ 5.4:1 on every surface.
  • The only attention effect: one 600 ms soft hn-teal-tint background fade (.hl-highlight, HoneLENS.highlight(el)) when a result appears or a state changes. Once per event, one element at a time.
  • No looping pulse, flash, shimmer, skeleton shimmer or spinner. Loading is a static clock icon and a sentence ("Looking up…"), or a determinate Progress bar.
  • prefers-reduced-motion: transforms removed, color changes ≤ hl-dur-reduced (80 ms), highlight becomes a static tint.

States

Every interactive component has default, hover, focus-visible, pressed, disabled, loading and error. Disabled uses hn-panel fill, hn-hair border, hn-slate text. Error is amber, never red. Loading never spins.

Iconography

Original HoneLENS line icons (window.HoneLENS.icons): 24 grid, 1.75 stroke, square caps and mitre joins to echo the HoneNurse bevel, currentColor only, 16/20/24 px. Always paired with a word. No medical clichés (crosses, hearts, stethoscopes, pulse lines), no sparkles, no chat bubbles.

Logo

There is no HoneLENS logo. In the panel set "HoneLENS" in Plex Sans semibold as plain text. The Chrome toolbar uses the HoneNurse app icon alone at 16/32/48/128 px. Never put the slogan in the toolbar or panel. Logo files are in the Logos group, copied from the brand doc.

Accessibility

AA everywhere (text ≥ 4.5:1 in both themes, controls and icons ≥ 3:1). Works at 200 % zoom (the panel becomes ~180 CSS px: tabs scroll, tables scroll inside hl-table-wrap). Full keyboard access with visible focus. Every chip, toggle and segment has a text state. Screen-reader labels on icon buttons. Forced-colors mode supported.

Using the code

Load assets/Code/honelens-tokens.css (all tokens as CSS variables, light + dark, OS-following with a data-theme override), then honelens-components.css, then honelens-icons.js from a bundled file (MV3 forbids inline scripts). Use the hl- classes as the component previews show. .is-hover, .is-focus, .is-active exist only for documentation.
